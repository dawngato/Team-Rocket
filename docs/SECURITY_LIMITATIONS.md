# Security limitations

HimVote is an educational prototype using synthetic data. It must not be used for a real campus election without independent security, cryptographic, privacy, accessibility, legal, and operational audits.

The current repository does not prove:

1. Complete anonymity against colluding identity, casting, network, or infrastructure operators.
2. Coercion resistance or receipt freeness.
3. Protection from a compromised voter device, browser, mobile OS, or desktop OS.
4. Secure operation of a separately governed witness organization.
5. Public chain finality or a production smart contract deployment.
6. Eligibility correctness beyond the local synthetic roster fixtures.
7. Production suitability of Profile VEEM. It is a development adapter, not a selected external voting engine.
8. Native Android, iOS, or Windows release readiness in this Linux workspace.

The verifier must report limited or unverifiable properties when the necessary independent evidence is absent. A successful local test run is not a blanket security result.
